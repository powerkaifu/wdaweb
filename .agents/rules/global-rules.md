# 全域補充守則

## Git Commit 格式規範

- 使用繁體中文撰寫 Commit 訊息。
- 格式：類型: 說明
- 類型清單：
  - feat: 新增功能
  - fix: 修復問題
  - docs: 文件更新
  - style: 格式調整（不影響邏輯）
  - refactor: 重構（不新增功能也不修復 bug）
  - chore: 建置或輔助工具調整

## 全域共用架構與設計系統紀律（最高優先級，強制遵守）

在新增任何功能、修復問題或調整 UI 時，**嚴禁孤島式開發，必須永遠站在全域共用架構的視角**，嚴格謹守以下規範：

1. **全域文字字級與中高齡友善（Typography & Accessibility）**：
   - 全站所有文字大小必須嚴格符合 `style.css` 定義的 `:root` 變數階梯（`text-xs` 至 `text-6xl`）。
   - **嚴格禁止**在任何組件中發明 `text-[10px]`、`text-[11px]` 等任意硬編碼極小字級。
   - **中高齡與老花眼友善底線**：全站所有重要內文、卡片說明、反思文字與收穫標籤**一律維持 `text-base`（16px）或以上**，行高維持 1.7~1.8 寬闊舒展，杜絕瞇眼吃力感。
2. **全站頂級中西文字型分流系統（Font Pairing & Glyph Fallback）**：
   - **繁體中文**：一律由 Google Fonts **思源黑體（`Noto Sans TC` / `Source Han Sans TC`）**渲染，筆畫剛健、大器清晰。
   - **英文字母與阿拉伯數字**：一律優先由 Google Fonts **`Plus Jakarta Sans`** 渲染，呈現頂級現代前端科技與 AI 未來感。
   - **程式碼與等寬序號水印**：一律由 **`JetBrains Mono`** 渲染。
3. **大器單行標題與版面防碎裂換行紀律（Single-Line & Grid Rhythm）**：
   - **標題單行原則**：全站區塊大標題（14~20字）在桌機寬螢幕上一律以「大器單行」呈現，**禁止隨意加入 `<br class="hidden sm:inline" />` 或將標題強行拆切成兩行**。
   - **4 欄網格防窄防碎**：多卡片網格（如起點軌道、核心技術、實體價值）必須推遲至 **`xl:grid-cols-4`**（1280px+）啟用，在 1024px~1279px 筆電螢幕維持 2 欄寬版佈局；卡片 Padding 精簡為 `p-5 sm:p-6`；內文字數嚴格精煉至 40~50 字黃金 2~3 行，杜絕垂直窄條折返閱讀。
4. **Hero 輪播文字頂部定錨防抖動紀律（Top-Anchored Zero-Jitter）**：
   - 輪播文字容器必須採用「頂部座標定錨（`absolute inset-x-0 top-0`）與響應式固定安全高度階梯（`h-[260px] sm:h-[220px] lg:h-[200px] xl:h-[185px]`）」，**嚴禁使用 `justify-center`**，確保標題首行位置 100% 絕對靜止，下方按鈕與指標絕不上下抽動。
5. **全域色彩系統（Color Palette）**：
   - 主色調統一為電光青（`cyan-500` / `cyan-400`），深色底為 `slate-950` / `slate-900`。
   - 輔助色彩依語意統一：成功/成果使用 `emerald`、科技/時數使用 `blue`、津貼/亮點使用 `purple`、警告使用 `amber`。
   - 禁止在個別組件中私自撰寫脫離調色板的孤島色碼。
6. **全域狀態管理（Pinia Store Single Source of Truth）**：
   - 所有跨組件共用資料、後台 CMS 動態欄位、全站聯絡資訊，**一律統一收斂於 `useCmsStore`**。
   - 嚴禁在個別 Section 組件中繞過 Store 私自硬編碼資料。
7. **全域動效與滾動調度（GSAP & ScrollTrigger）**：
   - 全站滾動調度一律透過 GSAP `ScrollTrigger`，統一採用 `power2.out` 悠揚曲線與純 Y 軸平滑過渡，嚴禁 scale 膨脹突變與原生 scroll 監聽殘留。

## 程式碼提交前自我檢查清單

1. 本次修改是否有脫離全域文字字級階梯（是否有任何 `text-[*px]`）？
2. 本次色彩與樣式是否符合全站 Tailwind 系統與暗黑科技風格？
3. 本次資料來源是否收斂於 Pinia Store（`useCmsStore`）且具備防禦性 Fallback？
4. 是否有殘留不必要的 console.log 或 print 除錯語句？
5. 是否所有 async 函式都有 try-catch 錯誤處理？
6. 是否有硬編碼的敏感資訊（密鑰、URL）未移至環境變數？
7. 是否有調整到官方核心資料（台灣就業通連結、電話）而未向使用者確認？

## 縮排規範

- 前台（TypeScript / Vue）：2 個空格。
- 後端（Python）：4 個空格（遵循 PEP8）。

## 動畫與視覺特效測試專區規範

- **專屬測試路由**：`/#/kaifu-lab`（對應組件 `GlowLabView.vue`）為使用者的**專屬動畫與視覺效果測試區**。
- **介面規範**：
  - 固定採用**左側懸浮 HUD 控制台**佈局。
  - **100% 全螢幕純淨測試體驗**：在該分頁下強制隱藏 Navbar、Footer 與全站滾動進度條。
  - 未來所有新研發的動畫、微互動、卡片 3D 特效、光暈與流光實驗，一律在此分頁提供即時切換與預覽，供使用者驗收與體驗。
